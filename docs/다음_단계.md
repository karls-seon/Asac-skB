## 바로 할 일

### 1. 필터 + 랭킹 함수 (합성 데이터 없이 시작 가능)

요금제 2,772행은 실데이터라 이미 있다. 입력 dict를 받아 필터 걸고 정렬해서
상위 N개를 내는 함수 하나면 된다. LLM·군집화·합성 데이터 전부 필요 없다.

먼저 만들어야 하는 이유: 아래 질문들이 **돌려보면 답이 나온다.**
- 동점 10개가 실제로 문제인가, 필터만으로 자연히 갈리는가
- 어떤 입력 조합에서 후보가 0건이 되는가
- 알뜰폰 80% 편중이 실제 추천 결과를 어떻게 만드는가

### 2. 스펙 → 적정가 회귀 (실데이터 ML)

`(data_gb, data_unlimited, voice_unlimited, sms_unlimited, carrier_type, ...)`
에서 `discounted_fee`를 예측하고, **실제가 - 예측가**를 가성비 점수로 쓴다.

정답이 실제 시장 가격이라 순환이 없다. 1번에서 남는 동점을 가르는 근거가 되고,
발표에서 "ML을 어디에 썼나"에 대한 답도 된다.

### 3. 합성 고객 (작게)

용도는 **훈련이 아니라 커버리지 테스트**다. 어떤 입력 조합에서 후보가 0건인지
찾는 것. 수백 명이면 충분하고 생성 규칙은 단순해도 된다.

분포는 [KISDI 변수 목록](KISDI_변수목록.md)의 실측값을 따른다.

## 멘토에게 확인할 것

1. **원자료(마이크로데이터) 신청이 가능한가?**
   코드북에는 변수별 주변분포만 있어 변수 간 상관을 살릴 수 없다.

2. **데이터 사용량 GB는 어디서 구하나?**
   미디어패널조사에는 문항 자체가 없다.

3. **합성 데이터 레이블의 단위가 요금제 개별인가, 티어인가?**
   개별이면 클래스 2,426개에 표본이 클래스당 1.4개꼴이라 학습이 성립하지 않는다.

4. **레이블을 만드는 규칙과 비교 대상인 rule-based 모델이 같은 것인가?**
   같으면 rule-based가 100%로 고정되어 비교가 성립하지 않는다.
   (다만 ML 정확도를 "누가 이기나"가 아니라 **진단 지표**로 읽으면 쓸모가 있다 —
   정확도가 낮게 나오는 것 자체가 "입력 변수만으로는 요금제가 결정되지 않는다"는
   증거가 된다. 실제로 예산 3만 + 데이터 20GB 조건에서 후보가 370개 남는다.)
