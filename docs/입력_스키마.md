# 입력 스키마

추천 요청 1건에 들어오는 값의 정의. 요금제 테이블
(`data/final/통신요금제_통합데이터_최종.csv`)의 어느 컬럼에 어떻게 붙는지까지
1:1로 적는다.

값은 두 종류로 나눈다. **섞어서 한 테이블에 두지 않는다.**

| | A. 관측 | B. 상담 입력 |
|---|---|---|
| 출처 | 통신사가 이미 갖고 있는 사실 | 사용자가 추천받는 그 순간에 답하는 것 |
| 합성 데이터 | 만든다 | 만들지 않는다 |
| ML 피처 | 될 수 있다 | **될 수 없다** — 학습 데이터에 존재하지 않는 값 |
| 쓰이는 곳 | 학습 + 추론 | 추론 시점 필터로만 |

B를 학습 피처로 쓰면 훈련 때 있던 입력이 실서비스에 없는 상태가 된다.

---

## A. 관측

| 변수 | 타입 | 예 | 붙는 컬럼 |
|---|---|---|---|
| `age` | int | `27` | `age_condition` |
| `data_gb_month` | float | `18.5` | `data_gb` / `data_unlimited` |
| `data_unlimited_need` | bool | `True` | `data_unlimited` |
| `voice_heavy` | bool | `True` | `voice_unlimited` |
| `sms_heavy` | bool | `False` | `sms_unlimited` |
| `tethering_gb_month` | float | `3.0` | `tethering_support` |
| `current_plan_id` | str | `1681_초이스130` | `plan_id` |
| `current_fee_krw` | int | `69000` | `discounted_fee` |

이용량은 **월 1행**이다. 여러 달을 쌓아야 할 이유(사용량 예측)가 실제로
생기면 그때 행을 늘린다.

`current_plan_id` / `current_fee_krw`는 추천 근거가 아니라 **비교 기준**이다.
"지금보다 월 얼마 아낀다"를 말하려면 있어야 한다. 없으면(신규 가입) 비워 둔다.

> **`data_gb_month`와 `data_unlimited_need`를 둘 다 두는 이유**는
> [KISDI 변수 목록](KISDI_변수목록.md) 참고. 합성 데이터의 분포 근거로 쓰는
> 한국미디어패널조사에 **데이터 사용량 GB 문항이 없다.** 무제한 가입 여부만
> 있다(43.2%). GB는 아는 사람만 답하는 선택 입력으로 두고, 합성 데이터는
> 무제한 여부 기준으로 만들어야 분포에 근거가 붙는다.

## B. 상담 입력

| 변수 | 타입 | 예 | 붙는 컬럼 | 쓰임 |
|---|---|---|---|---|
| `budget_krw` | int | `30000` | `discounted_fee` | 필터 |
| `mvno_ok` | bool | `True` | `carrier_type` | 필터 |
| `preferred_mno` | `KT`\|`SKT`\|`LGU+`\|`None` | `None` | `host_mno` | 필터 |
| `network_pref` | `5G`\|`LTE`\|`None` | `None` | `network_gen` | 필터(빈값 통과) |
| `ott_want` | list[str] | `["넷플릭스"]` | `ott_options` | **가점** |
| `smart_device_want` | bool | `False` | `smart_device_benefit` | **가점** |

> **`mvno_ok`가 결과를 제일 크게 가른다.** 전체 2,772행 중 MVNO가 2,229행(80%)이다.
> 예산 3만원 + 데이터 20GB 조건에서 후보가 370개인데, `mvno_ok=False`면 **2개**로
> 떨어진다. 안 물어보고 기본값을 잡으면 안 되는 값이다.
>
> 실제 시장은 반대다 — 조사상 알뜰폰 가입자는 **4.1%**뿐이다. 즉 대부분의
> 사용자에게 추천 결과는 "알뜰폰으로 갈아타세요"가 된다. 그게 맞는 추천이더라도
> `mvno_ok`를 안 물으면 받아들여지지 않는다.

---

## 왜 통화·문자는 bool이고 데이터만 GB인가

같은 스펙이라도 컬럼마다 결측률이 다르다. **결측이 큰 컬럼으로 거르면, 스펙이
나빠서가 아니라 사이트가 값을 안 적어서 탈락하는 요금제가 생긴다.**

| 컬럼 | 결측 | 쓰임 |
|---|---|---|
| `carrier_type` · `host_mno` · `data_unlimited` · `voice_unlimited` · `sms_unlimited` · `tethering_support` | **0%** | 필터 |
| `discounted_fee` | 2.1% | 필터 |
| `data_gb` | 14.1% | 필터 |
| `network_gen` | 9.6% | 필터(빈값 통과) |
| `voice_minutes` | 61.8% | 가점만 |
| `sms_count` | 60.5% | 가점만 |
| `ott_options` | 90.1% | 가점만 |

"통화 몇 분 쓰세요"를 물어봐야 `voice_minutes`에 붙는데 그 컬럼은 61.8%가 비어
있다. 반면 `voice_unlimited`는 결측 0%다. 그래서 **거칠게 묻는다** —
`voice_heavy` bool 하나면 결측 없는 컬럼에 붙는다.

## 필터 의미

| 변수 | 규칙 |
|---|---|
| `budget_krw` | `discounted_fee <= budget`. 빈값인 2.1%는 **탈락시킨다**(가격 모르면 추천 못 함) |
| `data_gb_month` | `data_unlimited == True` **또는** `data_gb >= 사용량`. `data_gb` 빈값 + 무제한 아님 = 탈락 |
| `data_unlimited_need` | `True`면 `data_unlimited == True`만 |
| `voice_heavy` | `True`면 `voice_unlimited == True`만 |
| `sms_heavy` | `True`면 `sms_unlimited == True`만 |
| `tethering_gb_month > 0` | `tethering_support != "unsupported"`. **`undisclosed`(24%)는 남긴다** — 미공시지 미지원이 아니다. 남기되 결과에 "테더링 미공시"라고 표시 |
| `age` | `age_condition`이 빈 행(2,485행)은 항상 통과. 값이 있는 287행은 조건이 맞을 때만 |
| `mvno_ok=False` | `carrier_type == "MNO"`만 |
| `preferred_mno` | 값이 있으면 `host_mno` 일치만. `None`이면 전부 |
| `network_pref` | 값이 있으면 일치 + **빈값(265행)도 통과**. 빈값은 "모름"이 아니라 "5G·LTE 둘 다 가입 가능"이다 |
| `ott_want` `smart_device_want` | **필터 아님.** 겹치면 가점 |

## 혜택은 전부 가점이다 (필터 금지)

혜택 컬럼의 빈값은 "미공시"가 아니라 **진짜 없음**이다. 요약 컬럼과 혜택
테이블을 대조하면 불일치가 0건이다(`ott_options` 274 = 혜택테이블 OTT/구독 274,
`membership_grade` 294 = 멤버십 294, `smart_device_benefit` 297 = 스마트기기 297).

그래서 원리상 필터로 쓸 수 **있는데**, 쓰면 안 된다:

```
예산 3만원 이하                 2,006개
  + "OTT 있어야 함"                 0개
  + "스마트기기 혜택 있어야 함"        0개
  + "멤버십 등급 있어야 함"           0개

예산 5만원까지 올려도 + OTT 필수 -> 0개
```

혜택이 붙은 요금제가 **전부 5만원 초과**다. 필수로 걸면 *"OTT 원함 = 최소 5만원"*
이 강제된다. 사용자는 "있으면 좋다"는 뜻으로 답한 것이지 예산을 올린 게 아니다.

**혜택 유무가 가격대와 얽혀 있어서, 혜택을 필수로 걸면 요금제가 아니라 가격대를
고르는 것이 된다.** 가점으로 두면 예산 안에서 혜택 있는 게 위로 올라오고,
없으면 없는 대로 추천이 나온다.

### 안 받는 것

| 컬럼 | 사유 |
|---|---|
| `membership_grade` | 사용자가 먼저 요구하는 값이 아니다. 비싼 요금제에 딸려오는 결과 → 결과에만 표시 |
| `selected_option` | **중복.** `ott_want`로 "넷플릭스"를 받으면 `selected_option == "넷플릭스"`인 행이 알아서 매칭된다 |
| `monthly_fee` | `discounted_fee`와 중복(1,971행이 서로 다름). 사용자가 아는 건 실제 내는 돈 하나 |
| `data_throttle_speed` | 일반 사용자는 "소진 후 5Mbps" 개념을 모른다. 무제한 여부로 충분 |
| `voice_extra_minutes` | 영상·부가통화 분수를 요구사항으로 말하는 사용자는 없다 |

> ⚠️ `ott_options`의 **MVNO 0%는 파싱 결함**이다(시장 구조가 아님). 모요에서 온
> 혜택 2,322건이 전부 `사은품/페이백` 한 카테고리로 들어가 있는데, 그 안에
> `밀리의 서재 평생 구독 0원` 같은 OTT가 94건, `SOLO결합 데이터 N GB 지급` 같은
> 추가데이터가 190건 넘게 섞여 있다. 고치기 전에는 OTT 가점이 알뜰폰을 부당하게
> 깎는다.

## 동점

필터를 다 걸어도 `(discounted_fee, data_gb, data_unlimited)`가 완전히 같은
요금제가 남는다(예산 3만·20GB 조건에서 최다 10개). 가격·스펙만으로는 이 10개의
순서에 근거가 없다.

**입력값을 더 받아서 풀 문제가 아니다** — 사용자에게 물어볼 수 있는 건 위가
거의 전부다. 남은 동점은 요금제 쪽 정보로 갈라야 한다. 스펙에서 적정가를
회귀로 예측하고 실제가와의 차이를 가성비 점수로 쓰면, 실제 시장 가격이 정답이라
순환 없이 동점을 세울 수 있다.
